# 树莓派现场排查命令手册

适用目录：`hornet_model2_ncnn_model`

适用服务：
- `hive-sensor`
- `hive-vision`
- `hive-transfer`

说明：
- 本手册用于现场排查“采集不准、存储异常、上传失败”。
- 命令默认在树莓派终端执行。
- 你这边 `OLED` 自测已经通过，所以这里不再把 OLED 作为主排查项。

## 1. 先确认当前代码和配置

进入项目目录：

```bash
cd /home/first/Desktop/yolov8/hornet_model2_ncnn_model
pwd
ls -lah
```

看当前关键配置：

```bash
grep -nE "host:|port:|client_id:|publish_interval_seconds:|cloud_broker_url:|cloud_enabled:|hx711_|dht_|ir_|gps_|humidifier_|oled_" config.yaml
```

看环境变量文件是否存在：

```bash
ls -lah .env
sed -n '1,120p' .env
```

如果不想把密码明文打出来，只看变量名：

```bash
grep -nE "^SMART_HIVE_" .env | sed 's/=.*$/=***/'
```

## 2. 先看 systemd 服务是否正常

看三个服务是否都在运行：

```bash
sudo systemctl status hive-sensor hive-vision hive-transfer --no-pager
```

看是否开机自启：

```bash
sudo systemctl is-enabled hive-sensor hive-vision hive-transfer
```

看最近 200 行日志：

```bash
sudo journalctl -u hive-sensor -n 200 --no-pager
sudo journalctl -u hive-vision -n 200 --no-pager
sudo journalctl -u hive-transfer -n 200 --no-pager
```

实时盯日志：

```bash
sudo journalctl -u hive-sensor -f
sudo journalctl -u hive-vision -f
sudo journalctl -u hive-transfer -f
```

如果要重启三项服务：

```bash
sudo systemctl restart hive-sensor
sudo systemctl restart hive-vision
sudo systemctl restart hive-transfer
```

## 3. 排查是否还跑着旧进程

当前代码已经走 `sensor_process.py / vision_process.py / transfer_process.py`。
如果还看到旧的 `IotIngestUploader`、旧脚本名、旧 Python 路径，通常说明板子上还有旧服务或旧进程残留。

看 Python 进程：

```bash
ps -ef | grep -E "sensor_process|vision_process|transfer_process|IotIngestUploader|python" | grep -v grep
```

看 systemd 服务定义实际指向哪里：

```bash
sudo systemctl cat hive-sensor
sudo systemctl cat hive-vision
sudo systemctl cat hive-transfer
```

如果服务定义还是旧路径，重新安装服务：

```bash
cd /home/first/Desktop/yolov8/hornet_model2_ncnn_model
sudo bash install_services.sh
```

## 4. MQTT 连通性排查

这是当前最优先项。之前日志里已经出现过：
- `Connection refused`

先看本机 Broker 是否存在：

```bash
sudo systemctl status mosquitto --no-pager
ss -lntp | grep 1883
```

如果 Broker 不在本机，确认配置不要写 `127.0.0.1`：

```bash
grep -nE "host:|cloud_broker_url:" config.yaml
grep -nE "^SMART_HIVE_MQTT_HOST|^SMART_HIVE_MQTT_PORT|^SMART_HIVE_CLOUD_" .env
```

测试能不能连本机 MQTT：

```bash
mosquitto_sub -h 127.0.0.1 -p 1883 -t "smarthive/pi5/sensors" -C 1 -v
```

测试能不能连远端 MQTT：

```bash
mosquitto_sub -h 你的MQTT服务器IP -p 1883 -t "smarthive/pi5/sensors" -C 1 -v
```

如果 Broker 开了账号密码：

```bash
mosquitto_sub -h 你的MQTT服务器IP -p 1883 -u "用户名" -P "密码" -t "smarthive/pi5/sensors" -C 1 -v
```

从板子主动发一条测试消息：

```bash
mosquitto_pub -h 127.0.0.1 -p 1883 -t "smarthive/pi5/sensors" -m '{"deviceId":"pi5-test","timestamp":1710000000000,"sensors":[{"type":"temperature","value":25.5,"unit":"C"}]}'
```

同时观察 `transfer_process` 是否收到 MQTT 并上报实时数据：

```bash
sudo journalctl -u hive-transfer -f | grep -E "MQTT connected|Subscribed to|MQTT→实时缓存|\\[UPLOAD\\]|IoT ingest"
```

正常情况下应该连续看到：
- `MQTT connected to 127.0.0.1:1883`
- `Subscribed to: smarthive/pi5/sensors`
- `[DATA] MQTT→实时缓存已更新`
- `[UPLOAD] 成功上传实时数据到后端`

如果只有 `MQTT connected` 但没有 `[DATA]`，说明 `sensor_process` 没有发布到同一个 topic，重点检查 `mqtt.data_topic`。

如果有 `[DATA]` 但 `[UPLOAD]` 失败，说明 MQTT 本地链路正常，问题在后端地址或 token，重点检查：

```bash
grep -nE "beehive_url:|api_token:" config.yaml
grep -nE "^SMART_HIVE_API_TOKEN|^SMART_HIVE_BEEHIVE_URL" .env | sed 's/=.*$/=***/'
curl -sS -H "Authorization: Bearer $SMART_HIVE_API_TOKEN" http://121.196.155.132/api/iot/monitor
```

从树莓派直接模拟一次实时上报到 Node.js：

```bash
curl -sS -X POST "http://121.196.155.132/api/iot/ingest" \
  -H "Authorization: Bearer $SMART_HIVE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"deviceId":"pi5-vision-client","timestamp":1710000000000,"sensors":[{"type":"temperature","value":25.5,"unit":"C"},{"type":"humidity","value":61.2,"unit":"%"},{"type":"out_temp","value":22.1,"unit":"C"},{"type":"out_humi","value":58.8,"unit":"%"},{"type":"weight","value":12.34,"unit":"kg"},{"type":"bee_in","value":3,"unit":"count"},{"type":"bee_out","value":2,"unit":"count"},{"type":"hornet_count","value":1,"unit":"count"}]}'
```

看本机网络是否通后端或 MQTT 服务器：

```bash
ping -c 4 你的MQTT服务器IP
nc -vz 你的MQTT服务器IP 1883
curl -I http://你的后端IP/api/health
```

## 5. 传感器采集排查

### DHT22

先看日志里有没有初始化成功和读取异常：

```bash
sudo journalctl -u hive-sensor -n 200 --no-pager | grep -E "DHT|温湿度|读取异常"
```

如果你想开更详细日志：

```bash
cd /home/first/Desktop/yolov8/hornet_model2_ncnn_model
python3 sensor_process.py --config config.yaml --diagnostics --verbose
```

### HX711

如果日志里出现 `hx711 library not installed`，先确认依赖：

```bash
python3 -c "import hx711; print('hx711 ok')"
pip show hx711-rpi-py
```

如果没装：

```bash
pip install hx711-rpi-py
```

确认 GPIO 引脚配置：

```bash
grep -nE "hx711_dout_pin|hx711_sck_pin|hx711_reference_unit|hx711_tare_on_start" config.yaml
```

做一次最小化称重自检：

```bash
python3 - <<'PY'
from hx711 import HX711
hx = HX711(dout_pin=5, pd_sck_pin=6)
hx.set_reading_format("MSB", "MSB")
hx.set_reference_unit(1.0)
hx.reset()
hx.tare()
print("raw weight:", hx.get_weight(5))
hx.power_down()
hx.power_up()
PY
```

注意：
- `hx711_reference_unit` 不校准，读出来也不准。
- 这一步只验证“能不能读”，不代表“已经准确”。

### IR 蜜蜂计数

如果日志里出现：
- `IR initialization failed: Cannot determine SOC peripheral base address`

先看 GPIO 库能不能正常导入：

```bash
python3 - <<'PY'
import RPi.GPIO as GPIO
print("RPi.GPIO ok", GPIO.VERSION)
PY
```

看系统型号：

```bash
cat /proc/device-tree/model
uname -a
```

Pi 5 上建议额外确认 `rpi-lgpio` / `gpiozero` 兼容层：

```bash
pip show rpi-lgpio
pip show gpiozero
```

看配置引脚：

```bash
grep -nE "ir_enabled|ir_outer_pin|ir_inner_pin|ir_active_low|ir_debounce_ms|ir_direction_window_ms" config.yaml
```

实时观察 GPIO 事件时，可先只跑传感器进程：

```bash
cd /home/first/Desktop/yolov8/hornet_model2_ncnn_model
python3 sensor_process.py --config config.yaml --diagnostics --verbose
```

### GPS

看串口设备是否存在：


看配置：

```bash

    print(ser.readline().decode('ascii', errors='ignore').strip())
ser.close()
PY
```

## 6. 小时缓存与补传排查

现在小时数据走 SQLite 本地缓存，再通过 MQTT 补传。

看本地缓存文件是否存在：

```bash
ls -lah /home/first/Desktop/yolov8/hornet_model2_ncnn_model/*.db
```

看小时缓存库里有多少条：

```bash
sqlite3 /home/first/Desktop/yolov8/hornet_model2_ncnn_model/telemetry_hourly_cache.db "select count(*) from telemetry_cache;"
```

看最近 10 条缓存：

```bash
sqlite3 /home/first/Desktop/yolov8/hornet_model2_ncnn_model/telemetry_hourly_cache.db "select id, device_id, hour_bucket, created_at_ms from telemetry_cache order by id desc limit 10;"
```

看某条缓存的 payload：

```bash
sqlite3 /home/first/Desktop/yolov8/hornet_model2_ncnn_model/telemetry_hourly_cache.db "select payload from telemetry_cache order by id desc limit 1;"
```

如果你想验证“断网缓存、联网补传”：

1. 先停掉 MQTT Broker 或把 `cloud_broker_url` 故意写错
2. 等一小时采样落本地
3. 恢复 Broker
4. 看 `hive-transfer` 日志里是否出现补传成功

看补传日志：

```bash
sudo journalctl -u hive-transfer -n 200 --no-pager | grep -E "HourlyMqttSync|补传|落盘|MQTT"
```

## 8. 常用“快速判断”命令

一次性看关键错误：

```bash
sudo journalctl -u hive-sensor -u hive-vision -u hive-transfer -n 300 --no-pager | grep -E "ERROR|WARNING|Connection refused|hx711|IR|GPIO|MQTT|Traceback"
```

一次性看关键配置：

```bash
grep -nE "host:|cloud_broker_url:|client_id:|hx711_|dht_|ir_|gps_|publish_interval_seconds|cloud_enabled:" config.yaml
```

一次性看 Python 依赖：

```bash
python3 - <<'PY'
mods = ["adafruit_dht", "board", "serial", "pynmea2", "hx711", "RPi.GPIO", "paho.mqtt.client"]
for name in mods:
    try:
        __import__(name)
        print(name, "OK")
    except Exception as e:
        print(name, "FAIL", e)
PY
```

## 9. 当前最值得优先排查的顺序

建议按这个顺序跑：

1. `systemctl status` 看三个服务和 `mosquitto` 是否正常
2. `journalctl` 看有没有 `Connection refused`
3. `mosquitto_sub / mosquitto_pub` 验证 MQTT 真能收发
4. `python3 -c "import hx711"` 验证体重依赖
5. `python3 -c "import RPi.GPIO as GPIO"` 验证 IR GPIO 兼容层
6. `sqlite3 telemetry_hourly_cache.db` 验证断网缓存是否真的落盘
